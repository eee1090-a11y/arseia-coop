# 아르세이아의 견습생 · 함께 작업하는 AI를 위한 원칙과 히스토리

> 이 문서는 협업자(친구)의 Claude가 **작업을 시작하기 전에 반드시 읽는 문서**예요.
> 친구는 주로 **휴대폰(모바일) 최적화**를 맡아요. 게임 주인(저장소 주인)과 주인 쪽 Claude가 지금까지 지켜 온 규칙·결정·작업 방식을 정리했어요.
> 규칙이 이 문서와 대화 내용이 다르면, 먼저 친구에게 물어보고 친구가 주인과 확인하게 하세요.

---

## 0. AI가 먼저 기억할 다섯 가지

1. **저장은 절대 잃으면 안 돼요.** 주인은 예전에 마법사 캐릭터를 잃은 적이 있어요. 캐릭터 저장 키를 지우거나 덮어쓰는 코드는 어떤 이유로도 넣지 않아요.
2. **실제로 돌려 본 것만 "됐다"고 말해요.** "아마 괜찮을 것"은 통과가 아니에요. 빌드·#qa·화면 확인을 실제로 하고 결과 숫자를 적어요.
3. **main에 직접 올리지 않아요.** 가지(branch)를 만들어 PR로 보내요. 새 판 내기(판 번호, 패치노트 확정, 게임 주소, 서버 배포, 주인 PC 폴더)는 주인 쪽이 해요.
4. **그림·화면 배치 작업은 규칙·수치·적중 판정·저장을 바꾸지 않아요.** 휴대폰 최적화는 "보이는 방식과 속도"만 바꾸는 일이에요.
5. **사람에게는 쉬운 한국어로 말해요.** 주인과 친구는 개발자가 아니에요. 전문 용어 대신 무엇이 바뀌고 왜 그런지를 평범한 말로, 질문은 "예/아니오"나 짧은 보기로 답할 수 있게 해요.

## 1. 게임 한눈에 보기

- 이름: **아르세이아의 견습생**. 브라우저에서 도는 실시간 쿼터뷰(아이소메트릭) 액션 RPG. 디아블로 2 같은 손맛이 목표.
- 영감: WoW, 디아블로 2, 테일즈위버, 엘더스크롤, 라그나로크, 드래곤라자. 주인은 마법사·사제를 좋아해요.
- 목표: 친구 2~3명이 파티로 사냥하는 게임. 파티가 혼자보다 조금 더 보상이 좋고, 보스는 협동.
- 형태: HTML 파일 하나(`game.html`, 약 3.5MB) + 옆에 두는 음악(`audio/music/*.mp3`)·그림(`img/flare-*.js`)·앱 설치 파일(`app/`).
  - 소스는 `source/v5/` 의 조각 파일들을 `build.sh` 순서대로 이어 붙인 하나의 큰 함수예요.
- 같이 하기: Node 중계 서버(`server.js`)를 Render(무료)에서 돌려요. 이 저장소의 `main` 이 바뀌면 Render가 자동으로 다시 배포해요.
- 직업 4개: 마법사, 사제, 전사, 궁수. 전사·궁수도 마나를 써요.
- 최고 레벨 140. 1차(1~49), 2차(50~99), 3차(100~140) 전직.
- 난이도: 보통/악몽/지옥. 저장 칸 8개. 마을 4곳(브렌힐, 윌로벤, 헤이븐 교차로, 왕도 아르덴)과 여러 지역·던전.
- 마법 체계의 출발점은 주인의 설정 「룬의 계승자」. 다른 게임에서 빌려 와도 되지만 아래 규칙을 지켜요.

## 3. 주인이 정한 설계 규칙

### 스킬·마법
- 마법은 많고 단계가 촘촘해야 해요. 낮은 단계와 높은 단계는 **눈으로 확 다르게** 보여요. 버프·치유는 눈에 보이는 효과가 있어야 해요.
- 스킬 설명에 **다른 게임 이름을 절대 쓰지 않아요.** 한 게임에서 그대로 따온 티가 나는 이름은 독자적인 이름으로 바꿔요(예: 「서클 오브 힐링」은 그대로, 「생츄어리」라고 부르지 않음).
- 개념이나 효과가 같은 스킬은 합쳐요. 쓸모없는 중복은 헷갈리게 해요.
- 수치는 **더하기로만** 늘어요(곱하기 중첩 금지). 버프 지속은 레벨마다 +30초, 최대 300초.
- 강한 마법 일부는 시전 시간이 있고 일부는 채널링이에요. 강한 마법은 쓰고 나서 잠깐 경직이 있어요. 채널링은 즉발·시전보다 보상이 커야 해요.
  - 채널링은 **한 번 탭하면** 서 있는 동안 계속돼요(움직이거나 다시 누르면 멈춤).
- 바닥 범위 마법은 진짜 범위로 맞아야 해요. 투사체·일반 마법은 화면 절반쯤(480, 궁수 540)까지만 닿아요(안전한 원거리 사냥 방지).
- 가장 강한 마법은 일찍 배울 수 없어요. 3차가 2차보다 강해질 여지를 남겨요.
- 속성 상성은 **정반대끼리만 ±20%**(불↔냉기, 번개↔대지, 빛·신성↔어둠).
- 사제: 큰 공격 버프는 짧게, 버프·치유를 돌려 쓰며 역할을 해요. 보호막은 겹치지 않아요. 한 명을 바로 치유하는 기술도 있어요.
- 파티용/나만 쓰는 기술을 확실히 표시하고, 파티 버프는 추적할 수 있어야 해요.
- 단축칸에는 스킬 레벨 대신 작은 즉발/채널/시전 표시만 해요. 스킬은 스킬 트리에서 끌어다 놓아요.

### 아이템
- +모든 스킬, +트리 옵션은 드물어요(+모든 스킬 최대 5). 유니크·세트(특히 상급 유니크)는 귀하게 느껴져야 해요.
- 쓸모없는 장비가 가방을 채우지 않게 해요. 물약은 단계가 있고 마시는 대기 시간이 있어요.

### 몬스터·지역·던전·의뢰
- 필드 몬스터는 혼자서도, 탱커 없는 2인으로도 잡을 수 있어요(한 대에 기본 HP의 15~30% 이하). 탱커는 보스에서 중요해요.
- 레벨대마다 내 빌드와 상성이 나쁘지 않은 사냥터가 있어야 해요.
- 던전은 다른 맵에 갔다 와야 새로 생기고, 같은 맵에 있으면 1시간에 한 번까지만 새로 생겨요.
- 의뢰: 메인 줄거리는 곁가지 의뢰와 확실히 달라 보여요. 중요한 의뢰(전직)는 열리면 알리고 어디서든 받을 수 있고 갈 곳을 보여 줘요. "같은 몬스터 N마리 잡기"를 반복시키지 않아요.
- 마을: NPC·물건이 겹치지 않고, 누구와 말하는지 헷갈리지 않아요.

### 소리·그림
- 배경음은 맵마다 하나, 절대 겹치지 않아요. **브라우저 음성 읽기(TTS)는 주인이 싫다고 했어요. 다시 넣지 않아요.**
- 그림은 손으로 그린 판타지 느낌(디아블로 2, 라그나로크, 테일즈위버, WoW). **픽셀 아트 금지.** 목표는 드래곤라자 수준.
- 내 캐릭터는 NPC보다 자세하고, 낀 장비가 보여요. 가벼운 무료 그림은 써도 돼요(출처 표시).
- 그래픽 작업 때문에 패치가 늦어지면 안 돼요. 준비된 것만 내보내요.
- 사용자가 프로그램을 새로 설치하거나 여러 단계를 거쳐야 하는 해결책은 피해요.

## 4. 직업 단계 (요약)

- **1차 Lv1~49:** 위계 1~8(열리는 레벨 1·5·10·16·23·31·38·45). 직업 시험(5·10·16·23·31·38·45)이 의뢰 스킬 포인트 20점을 줘요.
- **2차 Lv50~99:** 갈래 2개 × 기술 12개. 마법사 아크메이지/서머너, 사제 대심문관/대주교, 전사 가디언 나이트/버서커, 궁수 호크아이/레인저. 공격 마무리기는 재사용 60초.
- **3차 Lv100~140:** 갈래마다 기술 11개. 대마법사/정령왕의 계약자, 빛의 집행자/성자, 성벽의 군주/전쟁군주, 신궁/그림자 사냥꾼. 마지막 협동 보스 「재의 군주」 Lv140.
- 직업 체계를 바꾸는 큰일은 주인과 먼저 상의해요.

## 5. 휴대폰(모바일) 작업 안내 — 친구가 주로 할 일

### 지금 휴대폰에서 이렇게 돼요 (v22)
- `source/v5/mobile18.js` (v18): 폭 640px 이하. 위 왼쪽 버튼을 ☰ 하나로 접기, 강화를 작은 아이콘으로, 단축칸 정리.
- `source/v5/mobile22.js` (v22): `M22.mode()` = `'L'`(가로 휴대폰: 터치 + 가로 + 높이 500 이하) · `'P'`(세로, 폭 640 이하) · `''`(PC, 아무것도 안 바꿈).
  - **가로 화면이 기본.** 세로면 「가로로 돌려 주세요」 쪽지(닫을 수 있고 세로로도 플레이 가능).
  - 단축바는 **채워진 칸만** HP 구슬과 마나 구슬 사이에 보여요(44px). 저장된 칸(`P.bar`)은 그대로이고 보이기만 바꿔요.
  - 귀환 주문서는 물약 옆이 아니라 왼쪽 위 ☰ 옆. 던전·보스 싸움 중에는 한 번 더 물어요. 친구가 실수로 눌러 쫓겨난 일이 있어서 바꾼 거예요.
  - 카메라: 휴대폰에서 `CZ = 화면 배율 × (가로 .75 · 세로 .8)`. 화면 좌표는 모두 CZ로 나누므로(`rel`) 겨누기가 맞아요. 카메라를 바꾸면 이 계산을 꼭 지켜요.
  - 확대 잠금: viewport `maximum-scale=1, user-scalable=no`, `touch-action`, iOS 제스처 막기, 입력 칸 16px. 그래도 확대되면 「화면 원래 크기로」 단추.
- `tap20.js`: 채널링 탭 한 번. `dnd20.js`: 스킬 끌어 놓기(휴대폰은 꾹 누른 채 끌기). `wmap22.js`: 휴대폰 세계 지도(글자 크게, 손가락으로 밀기).
- 주인이 말한 남은 문제: 휴대폰 세계 지도가 아직 붐벼요(지역 20곳). 3차 궁극기는 몬스터 50마리 상대로 한 프레임 26~44ms예요.

### 휴대폰 작업 규칙
- **PC 화면은 그대로 둬요.** 휴대폰 분기(`M22.mode()`가 빈 문자열이 아닐 때) 안에서만 바꿔요.
- 화면을 깔끔하게. 손가락이 닿는 버튼(귀환, 물약, 단축칸)이 서로 너무 가깝지 않게. 위험한 버튼(귀환, 아이템 버리기)은 실수로 누르기 어렵게.
- 저장 칸·단축칸 배치(`P.bar`)·설정 키를 바꾸지 않아요. 새 설정이 필요하면 새 키를 만들고 "없으면 기본값"으로 읽어요.
- 새 기능은 되도록 **새 파일**(예: `mobile23.js`)에 넣고 `build.sh` 순서에 추가해요. 주인 쪽 v23 작업과 같은 파일을 덜 건드려야 합칠 때 충돌이 적어요. 각 파일 머리말에 무엇을 하는지, 어디에 붙는지 적어요(기존 파일처럼).
- `b5.js` 앞에 붙는 파일은 `b5.js` 의 `let`(pbody/panel/tab 등)을 바로 쓰지 말고 `setTimeout` 으로 미뤄요.

### 속도 최적화에서 이미 알아낸 것
- 느린 건 게임 계산이 아니라 **그리기**예요. 몬스터 50마리일 때 update()는 0.24ms뿐이에요.
- 메인 캔버스의 `imageSmoothingQuality='high'` 는 50% 느려져요. 메인은 `'low'`, 미리 구울 때만 `'high'`.
- 땅은 덩어리로 미리 구워 붙이고, HUD 갱신은 초당 15번이에요. 장식은 덩어리별로 묶어요.
- 음악은 파일 밖(`audio/music`)에서 흘려보내요. 디코딩한 곡은 2개 이하로 둬요(한 곡 40~50MB 메모리).
- 그림(`img/flare-*.js`)은 필요할 때만 불러오고, 없으면 코드 그림으로 대신해요.
- `#qa` 의 성능 점검은 JS만 재요. 실제 화면 속도는 `fps.cjs` 로 재요.
- 휴대폰 성능은 Playwright에서 터치·작은 화면(가로 844×390, 세로 390×844)과 CPU 느리게(CDP `Emulation.setCPUThrottlingRate` 4배 등)로 재서 바꾸기 전과 비교해요.

## 6. 작업 과정 (PR 하나마다)

1. **시작 전:** `main` 을 최신으로 받고, 새 가지를 만들어요(예: `mobile/hotbar-spacing`). 바꿀 파일과 이유를 친구에게 짧게 알려요.
2. **바꾸기:** `source/` 안만. 루트의 `game.html`, `server.js`, `package.json`, `audio/`, `app/`, `img/` 는 배포된 판이라 건드리지 않아요. 서버를 바꿔야 하면 PR에 따로 적고 주인과 상의해요.
3. **버그를 고쳤다면:** 그 버그를 잡는 시험을 `source/v5/qa.js` 에 하나 추가해요. 이미 있는 시험은 지우거나 끄지 않아요.
4. **점검 (모두 실제로 실행):**
   - 빌드: `bash source/v5/build-to.sh ../game-test.html` → `BUILD_OK`
