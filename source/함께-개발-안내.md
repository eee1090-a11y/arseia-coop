# 아르세이아의 견습생 · 함께 개발 안내

이 폴더(`source/`)에는 게임의 원본 소스가 들어 있어요. 친구(협업자)는 자기 Claude Code로 이 저장소를 열어 게임을 고치고, 바뀐 내용을 **풀 리퀘스트(PR)** 로 보내요. 새 판을 내는 일(판 번호, 게임 주소, 서버 배포)은 저장소 주인 쪽이 맡아요.

## 1. 처음 한 번 준비

1. 저장소 주인이 보낸 GitHub 초대 메일(또는 https://github.com/eee1090-a11y/arseia-coop/invitations )에서 **Accept invitation** 을 눌러요.
2. https://claude.ai/code 에 들어가 GitHub 계정을 연결해요(처음 한 번, 화면 안내대로).
3. 저장소 목록에서 **eee1090-a11y/arseia-coop** 을 골라 새 작업을 시작해요.

## 2. 고치고 싶은 것 부탁하기

Claude에게 평소 말투로 부탁하면 돼요. 예:

> 마법사 불덩이 스킬의 마나 소모를 조금 줄여 줘. 끝나면 #qa 돌리고 PR 올려 줘.

Claude가 이 저장소의 `CLAUDE.md`를 읽고 아래 규칙대로 일해요.

## 3. 소스 구조 (Claude용 요약)

- `source/v5/` — 게임 조각 파일들. `v5/build.sh` 에 이어 붙이는 순서가 있어요. 주요 파일 설명은 맨 아래 「파일 지도」.
- 빌드: `bash source/v5/build-to.sh ../game-내이름.html` → `source/game-내이름.html` (문법 검사 포함, `BUILD_OK` 가 나와야 함)
- 자가 점검 빌드: `bash source/qa-build.sh source/v5 ../game-qa.html`
- 자가 점검 실행: `node source/qa-run.cjs source/game-qa.html --timeout=1700` → 전부 통과해야 함(실패 있으면 종료 코드 1). 점검이 970개가 넘어 10분 넘게 걸릴 수 있어요. 음악은 저장소의 `audio/music/` 을 씀.
- 마법 적중 시험: `G=source/game-내이름.html node source/t11A.cjs`
- 저장 호환 시험: `node source/xsave.cjs 예전판.html 새판.html` (예전판은 저장소 루트의 `game.html` = 지금 배포된 판)
- 60초 실행 + 휴대폰 화면: `node source/r60.cjs source/game-내이름.html 출력폴더`
- 성능: `node source/fps.cjs source/game-내이름.html --scenes=town,fight,r9`
- 필요한 것: Node.js, Playwright(Chromium). claude.ai/code 환경엔 보통 이미 있어요.
- 빌드 결과(`source/game-*.html`, `*.check.js`, `qa-report.*`)는 저장소에 올리지 않아요(.gitignore).

## 4. 꼭 지킬 규칙

**올리는 방법**
- `main` 에 직접 올리지 않아요. 항상 새 가지(branch)를 만들어 PR로 보내요. `main` 은 실제 서버(Render)가 바로 가져가는 곳이에요.
- 저장소 루트의 `game.html`, `server.js`, `package.json`, `audio/`, `app/`, `img/` 는 배포된 판이에요. **건드리지 않아요.** 바꾸는 건 `source/` 안만.
- 한 PR에는 한 가지 주제만. PR 설명에 무엇을 바꿨는지, 어떻게 확인했는지, #qa 결과(몇 개 중 몇 개 통과)를 적어요.

**저장 안전 (가장 중요)**
- 저장 형식(localStorage `arseia-char-0` ~ `arseia-char-7`, 예전 키 `arseia-apprentice-save-v1`)을 바꾸지 않아요.
- 캐릭터 키를 지우는 코드(`removeItem`, `clear`, 빈 값 덮어쓰기)를 절대 넣지 않아요.
- 새 값이 필요하면 "없으면 기본값"으로 읽고, 예전 값은 지우지 않아요. 예전 저장을 불러와도 레벨·장비·스킬 점수·금화가 그대로여야 해요.

**점검**
- PR 전에 자가 점검(#qa) 전체 통과, 문법 오류 0, 콘솔 오류 0.
- 모든 공격 마법이 실제로 몬스터에게 맞아야 해요(t11A).
- 버그를 하나 고칠 때마다 그 버그를 잡는 시험을 `source/v5/qa.js` 에 하나 추가해요. 이미 있는 시험은 지우지 않아요.
- 그림만 바꾸는 작업은 규칙·수치·적중·저장을 바꾸지 않아요.

**게임 설계 원칙 (주인이 정한 것)**
- 스킬 설명에 다른 게임 이름을 쓰지 않아요. 다른 게임에서 그대로 따온 이름은 독자적인 이름으로 바꿔요.
- 수치는 더하기로만 늘어나요(곱하기 중첩 금지). 속성 상성은 정반대 속성끼리만 ±20%.
- 필드 몬스터는 혼자서도, 탱커 없는 2인으로도 잡을 수 있어야 해요.
- 그림은 손그림 판타지 느낌(픽셀 아트 금지). 휴대폰에서도 화면이 깔끔해야 해요.
- 큰 방향(새 직업, 새 지역, 밸런스 크게 바꾸기)은 먼저 주인과 상의해요.

## 5. 바뀐 내용이 게임에 들어가는 길

1. 친구가 PR을 올려요.
2. 주인 쪽 Claude가 새 판을 만들 때 열린 PR을 확인하고 합쳐요(merge).
3. 합친 소스로 전체 QA를 다시 돌린 뒤, 새 판 번호·패치노트를 붙여 게임 주소와 서버에 내보내요.

그래서 PR이 합쳐져도 바로 게임에 보이지 않을 수 있어요. 다음 판이 나올 때 함께 나가요.
